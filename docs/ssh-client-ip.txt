# SSH connection record client IP

## Why TCP frp forwarding shows `127.0.0.1`

The current SSH proxy is a plain TCP proxy:

```toml
[[proxies]]
name = "ssh"
type = "tcp"
localIP = "0.0.0.0"
localPort = 22
remotePort = 22222
```

With this topology, `frpc` accepts the public connection and opens a new
connection from the local machine to `sshd`. The SSH server therefore sees
the frpc process (often `127.0.0.1`) as its TCP peer. GPanel reads that peer
from `who -u` and `ss -tnp`; it does not receive the original TCP source
address.

A plain TCP connection cannot recover an address that was not transmitted.
GPanel must not replace this value with an address supplied by the browser or
an untrusted HTTP header, because that would make the connection record
incorrect and spoofable.

## Supported ways to preserve the source address

Use one of these deployment-level solutions if the public client address is
required:

1. **Source-address-preserving/transparent forwarding**: configure the network
   path so that `sshd` receives the original source address. The existing
   GPanel session discovery will then record that address.
2. **A trusted PROXY-protocol terminator**: configure frp's
   `transport.proxyProtocolVersion` (v1 or v2) and place a proxy-protocol-aware
   TCP frontend in front of `sshd`. The frontend must consume the PROXY header
   and forward a normal SSH stream to `sshd`; do not send the PROXY header
   directly to a stock OpenSSH listener.

The relevant frp option is documented in the official example:
<https://github.com/fatedier/frp/blob/v0.67.0/conf/frpc_full_example.toml>.
OpenSSH does not provide a `ProxyProtocol` setting in its server
configuration, so enabling the frp option alone is not sufficient.

## Verification

After changing the deployment, verify the same connection at each layer:

```sh
who -u
ss -tnp | grep sshd
```

Then open the SSH sessions page and confirm that its `登录IP` value matches
the address visible to `sshd`. For ordinary TCP frp forwarding, the expected
value remains the frp-side address (commonly `127.0.0.1`); GPanel cannot infer
the public address in that mode.

Do not enable proxy-protocol input on a listener unless every client reaching
that listener is trusted to use it. A listener that accepts both ordinary SSH
and untrusted PROXY-protocol headers can be spoofed or made incompatible with
normal SSH clients.
